# 阶段二：数组与局部路由记录

阶段二复用[共同宏](stage1-macros.md)的零锚点、自然数标记和静态布局。固定槽为 -3 到 `-(N+2)`，动态区从 `-(N+3)` 向负侧增长。帧长先解码，再初始化动态结构。

## 顺序数组

P006 使用单个负地址数组保存转换结果，元素均为自然数。指针槽 P 保存元素地址 X。name 只区分控制槽名称，不会自动划出多段互不相交的数组。

元素 v 到零最多两步，故 `X→v→标记→0` 最多三步，指针到零最多四步。相比旧版增加一层，以容纳通用比较的临时正地址标记。

重置指针：

```text
&0 ^1 &P ^5 &P ^1 &-B ^5
```

移动到下一元素：

```text
&0 ^1 &P ^5 &P *1 @- ^5
```

通过自环补齐零元素和非零元素的路径长度。读取仍是 `&P ~1 ~1`。写元素时令 0 指向 X，再令 X 自环，以 `^4` 写入自然数；读改写通过交换取出旧元素。自减要求旧元素为正，写表达式不能再读取被自环覆盖的旧元素。

顺序移动的分派数为常数；`seek(i)` 从头前移 i 次，仍为 `O(i+1)`。当前主解不再借 seek 实现值域桶。

## 独立记录

P007 使用 `tools/records.py` 的记录堆。每个节点四个单元：

| 地址 | 内容 |
| --- | --- |
| R | 永久零头 |
| R-1 | 自然数载荷 |
| R-2 | 自然数辅助字段，字节题中为零 |
| R-3 | 后继引用，零或记录头地址 |

节点身份与载荷分离，重复值和零值都可存储。堆指针每分配一条记录减四。本题只分配一次，不回收复用；排序全程重连已有节点，不创建新记录。

必须区分原始寻址图 `f(a)=memory[a]` 和逻辑后继 `g(R)=memory[R-3]`：记录头始终使 f(R)=0，链表则沿 g 遍历。链长增加不会加深引用的原始寻址路径。

引用槽 P 用：

```text
&0 ^1 &P ^3 &P ^1 EXPRESSION ^3
```

记录头或零到目标 P 恰好可在两步内到达，并以 P 自环补齐。引用推进先交换取出 R，再减三读取 next，最后 `^3` 写回；要求原引用非空。自然数载荷字段使用 `^4`，next 使用 `^3`，永久零头不可写。

## 线性所有权

每条链有 head、tail，空链二者均为零。追加节点要求它已摘离其他链且 next=0；非空追加只写旧 tail.next 和 tail。弹出头后，清掉返回节点的 next；若剩余链为空则同时清 tail。

拼接只修改 A.tail.next 与头尾引用，随后清空 B 的头尾，将节点所有权转移给 A。两链必须属于同一堆且节点集合不重叠。这些要求是宏契约，运行器不会自动检查。

稳定归并排序反复拆出左右段、摘出表头接入输出、拼接剩余段。因此每个节点在任一步都恰好属于源链、左右段、输出链或一个临时摘下节点，归并结束后全部回到源链。完整算法证明见 [P007](../problems/P007-byte-sort/proof.md)。

## 成本与边界

数组与记录堆分别独占同一动态地址区，当前题目从不混用。全部宏和临时槽在运行前静态生成。头尾和节点工作引用不得用自然数赋值宏；引用非空方可访问字段；调用者不得覆盖零头或制造重叠所有权。

P006 的顺序缓存为 O(n) 个单元；P007 为 n 条记录和固定数量控制槽。排序为 O(n log n) 次比较和 O(n log n) 次节点操作，数值比较本身仍可能逐次递减，不能称为单位成本。测试检查超字节载荷、稳定性、节点守恒、无环及临时链所有权清空。

这是显式数据结构的规模。上游的整行字符缓冲、Python 整数和 `defaultdict` 默认值读取产生的条目另计。
