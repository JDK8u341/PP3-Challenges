## 永久零头记录

`tools/machines.py` 的 Arena 在静态槽之后向负地址增长，每条记录含一个永久零头和八个字段。零头始终保存 0，字段可分别声明为自然数或零头引用。普通载荷使用四层写路由；引用使用三层写路由，以免旧的负地址引出静态槽的别名。

调用者必须保证字段类型不混用。写入表达式不能读取已经被临时设成自环的目标字段旧值；原地移动引用用交换取出旧引用后再跟随边。分配游标同样用交换后递减推进，不能用自读表达式覆盖自己。测试专门检查原地跟随、分配步长、自然数大载荷、零值覆盖及独立字段。

Chain 只追加节点、不拆除后继，故指令节点可被 PC、括号栈和配对边同时引用。字段 8 是后继；指令字段 4 是配对、5 是栈前驱。与排序中的所有权转移链不同，这里允许受约束的共享引用。

## 两个解释器的字符帧

输入按这个顺序组成：

```text
c\n
d\n
恰好 c 个源码字符，紧接恰好 d 个数据字符
```

c、d 先由两次整数 `@input` 读取，之后才启用字符输入。源码与数据之间没有隐含换行；如果分段处有 LF，它必须计入某个帧。比如 BF 输出输入字符 A：

```text
2
1
,.A
```

整数读取沿用 Python `int()` 拼写，负零等于零。负长度在两个长度头读完后输出 `ERROR\n`。字符码点限 0..255，NUL 为普通字符；输入处理器按行补回 LF，最后一行即使没有 LF 也会补回，这与阶段二一致。

先完整读取两个帧，校验字节范围、指令/token 和所有括号，成功后才执行。即使源码已发现错误，也要消费剩余两个帧；若此时提前 EOF，仍先发生宿主 `EOFError`，不会输出预定的 ERROR。帧外字符不处理，仍留在字符缓冲中。不同运行共享 IR 时，字符缓冲仍按 Runtime 隔离。

宿主帧的提前 EOF 与客体数据耗尽不同。P011 规定客体 EOF 写零；P012 规定输出 `ERROR\n` 并停止，保留已经输出的客体字符。语法错误则在执行前拒绝，不保留虚构的部分执行结果。

## 图上的四种应用

| 题目 | 动态结构 | 不依赖数值枚举的部分 |
| --- | --- | --- |
| P009 | 环面格点与方向边 | 复合方向取邻居，建立一次后反复复用 |
| P010 | 输入字符数组 | 通用十进制格式化，不按字符内容选择源码模板 |
| P011 | 指令链、括号配对边、双向数据带 | PC 直接跳转，按访问需要建立带节点 |
| P012 | token 链、指令链、带符号稀疏内存 | 地址是符号/幅值键，只扫描已访问记录 |

有限的八个方向、八条 BF 操作和十种 PP3 操作是规则分派，不是按输入值或地址值域生成分支。记录关系在运行时建立，静态源码不随输入大小重新生成。
