# 阶段二字符帧协议

本协议已由维护者确认。它描述现有 PP3 文本接口上的字符帧，不修改运行器，也不声称输入输出是原始二进制文件接口。

## 输入

1. 首行由标准 `@input` 读取长度 n。采用运行器原有的 Python 整数行解析；非法整数文本抛出 `ValueError`，没有输入则抛出 `EOFError`。
2. n 必须非负。负长度输出 `ERROR\n`，不读取字符负载。整数 `-0` 等价于 0。
3. 长度有效时，用 `@input_as_char` 精确消费 n 个逻辑字符，码点必须在 0..255。NUL 是合法数据，不作为终止标记。
4. `input()` 每次读取一整行，字符缓冲会补回 LF。这个真实或补回的 LF 都计入帧长度。例如输入 `3\nAB` 时，逻辑负载为 `A`、`B`、LF，而不是提前 EOF。
5. 若需要的字符仍不足，保留 `EOFError`。不把 EOF 转为 0，不打印部分结果，也不先打印 `ERROR` 再抛异常。
6. 遇到超范围码点后记录错误，并继续消费剩余帧字符；完整消费后只输出 `ERROR\n`。若排空期间提前 EOF，则按上一条抛异常。
7. 帧之外的字符不参与计算，超范围码点在帧外也不触发错误。`input()` 可能已经将同一行余下文本预读到字符缓冲中；这些字符仍保留给后续读取。

长度为零时不调用字符输入。每个问题一次运行处理一帧，且从新的 Runtime 开始。它不要求消费或校验整个标准输入。

## 输出

- P006：ASCII 字母执行 ROT13，输出其余字符原样，输出长度仍为 n，不额外补 LF。
- P007：按码点升序输出恰好 n 个字符，保留所有重复次数，不额外补 LF。
- P008：只把码点 9、10、11、12、13、32 作为空白。统计 LF 个数、最大连续非空白段个数和帧内字符数，输出 `行数 词数 字节数\n`。因为有效码点限于 0..255，题目把每个这样的字符按一个逻辑字节计数；不是把 Python 文本重新编码为 UTF-8 后计数。

三题都在整帧有效后才输出结果。wc 可以提前计算计数器，排序可以提前累计桶，但都不提前打印。

## 示例

```text
13
Hello, World!
```

P006 输出 `Uryyb, Jbeyq!`，不带末尾 LF；输入行的 LF 位于第 14 个逻辑字符，不属于这个长度为 13 的帧。

```text
6
a b
c
```

P008 的帧为 `a b\nc\n`，输出 `2 3 6\n`。
