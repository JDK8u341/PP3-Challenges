# 验证约定

每题提供中文题面及输入输出范围。只有已有解答标为 `solved`，其余题不提供伪解答，也不以尚未运行的算法草案标记完成。

已完成题的 `cases.json` 保存精确输入和预期输出；测试通过 PP3 原生运行器执行 `solution.pp3`。测试端可用 Python 作为独立参考模型，解答本身不能借它计算。

`tools/runtime.py` 会在执行前检查 IR：拒绝直接寻址，拒绝标准注册表之外的操作。它不替换运行器、内存或循环语义。

常规测试入口：

```text
python -B -m unittest discover -v
```

本轮归档的签名加法保留原有静态宏生成器，并用测试检查生成结果与提交的 `.pp3` 一致；另做有符号输入和零边界回归。更大范围的历史测试结果在 P001 证明中记载，但不以它替代新仓库当前运行结果。

后续每题记录：验证的输入范围、独立参考结果、循环不变量、耗时或步数测量方法，以及未覆盖的限制。代码长度、指令数和宿主秒数不能混为同一种指标。

阶段一的 `tests/test_stage1.py` 使用 Python 标准库参考模型差分，但 PP3 程序本身只含标准注册的 `@input`、`@print`、`@+`、`@-`、`@input_as_char`、`@print_as_char`。覆盖 P003 的有效、非法和 EOF 输入，P004/P005 的 `[-16,16]` 全枚举、额外较大边界样例，以及长除法的独立商余数检查。

阶段二的 `tests/test_stage2.py` 另外覆盖全部 256 个码点、ROT13 的双重变换、排序多重集、超过 255 个重复节点、六种 ASCII 空白、固定种子的 24 帧跨三题差分，以及负长度/Unicode 越界/提前 EOF 的零部分输出。还校验帧外缓冲、不同 Runtime 的隔离、数组和记录内容与普通槽不变量。

`tests/test_general.py` 直接复用主解的归并宏，检查长度 0..4 的三值序列、奇数段长、逆序与已排序、超字节载荷和相等的 100 位整数。辅助字段存原始序号，用于观察相等载荷的稳定性；检查完整节点地址集合、永久零头、无环和临时链控制槽清空。测试端的序列枚举用于找反例，解答本身不枚举值域。

新增裸整数解码测试先填充 80 个静态槽，再连续读取两数，覆盖两个原始值槽及其相邻输入。比较测试检查输入未变、零锚点及正地址恢复。测试范围有限，任意整数的推导条件单独写在共同宏证明中。

`python tools/measure_general.py` 用行跟踪观察原版 `Runtime.run` 的 handler 分派，比较固定旧提交与当前静态生成结果，并逐样本验证输出相同。报告位于 `results/general-algorithms.json`；它不替换 Runtime，不把分派数当宿主耗时，也不据有限样本承诺普遍加速。

全码点测试直接提供 `StringIO` 文本作为标准输入，并捕获字符输出，验证的是协议定义的逻辑字符，不是文件原始编码字节。所有程序仍运行在固定版本的原版 Runtime 中，未替换内存或执行循环。
