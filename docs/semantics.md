## 字符输入输出

以下描述的是固定提交的现有行为，不是新的语言修改：

- `@input` 每次读取一行整数。
- `@input_as_char` 将字符 `ord()` 写入 view；输入码点不会取模。
- 字符输入按行缓冲，补回行尾 LF。即使原输入最后一行没有换行，`input()` 读完后仍会补 LF。
- EOF 抛出 `EOFError`；DSL 不能把它当成“读取到了零”继续计算。
- `@print_as_char` 输出 `chr(view % 256)`，不附加换行，也不改变 view。
- 同一 Runtime 的字符操作共享自己的标准操作实例，不同 Runtime 相互隔离；`clear()` 清理本 Runtime 的输入缓冲。
- 整数输入不消费已缓存的字符。

所以当前接口是带缓冲的文本字符接口，不能未经说明就视为二进制文件 API。阶段二采用已确认的[长度字符帧](stage2-frames.md)，输入码点限制为 0..255，补回 LF 计入帧长。非字节 Unicode 输入不会被悄悄取模。

## 题目规约与未决项

P003 已冻结并实现：输入首行必须匹配 `[+-]?[0-9]+`，无周围空白；空行或非法字符输出 `ERROR\n`，有效值去除前导零和负零。P005 接受任意有符号整数，计算绝对值的最大公约数，并定义 `gcd(0,0)=0`。

P006/P007/P008 已冻结并实现：首行用 @input 读 n，再消费 n 个逻辑字符；负长度或完整帧内超范围字符输出 ERROR，提前 EOF 保留异常，均无部分结果。P008 仅以 ASCII 9..13、32 为空白，输出 `行数 词数 字节数\n`。详见[完整协议](stage2-frames.md)。

2026-11-07 已确认并完成 P009–P012：P009 小环面按八方向重复计数，零尺寸输出空文本；P010 沿用阶段二帧；P011 为模 256 单元、双向无限带、忽略非指令字符、客体 EOF 写零；P012 支持核心间接寻址/循环/字符 I/O 子集，客体输入耗尽输出 ERROR 并停止。详见各题题面、[双帧协议与支持范围](interpreters.md)。

客体的方言与错误协议已经单独冻结，不修改宿主 PP3 的规则；尤其 P012 的 ERROR 约定不等同于原版异常类型。未来若扩大子集或新增题目，仍需确认未决语义。
