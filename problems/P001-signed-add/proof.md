# PP3：支持负整数的 A+B 推导

本推导基于 `JDK8u341/PP3`，提交为：

```text
961ee939542c691ccfd3a374e6aca8d838dc40a6
```

这是原推导使用的版本。本仓库归档时另外在 `vendor/PP3` 固定的 `aceb4c532cf475f7b69fb623affc81c9f70e8c48` 上验证已有解答；原始寻址和算术语义未改动。

运行器原文件没有修改。调用条件保持为：

```python
builder = IRBuilder(op_map=std_register)
rt = Runtime(can_direct_addressing=False)
```

完整程序只调用 `@input`、`@print`、`@+` 和 `@-`，没有使用直接寻址，也没有增加自定义操作。

## 一、先明确间接寻址的含义

记当前内存映射为：

```text
f(a) = memory[a]
```

执行一条深度为 n 的间接指令时，从当前 `view` 出发，先沿内存映射跳转 n−1 次，得到最终操作地址：

```text
place = f^(n−1)(view)
```

随后：

| 指令 | 对最终地址执行的操作 |
| --- | --- |
| `~n` | `view = memory[place]` |
| `^n` | `memory[place] = view` |
| `*n` | 交换 `view` 和 `memory[place]` |

因此，`^3` 是先跳转两次，再向所得地址写入原来的 `view`。寻址用到的值和最终写入的值来自同一个 `view`，这正是构造赋值时需要解决的限制。

后文的 `X`、`EXPRESSION` 等是宏模板中的占位符，实际运行前必须展开为具体 DSL 指令。

## 二、为多变量存储建立约束

完整程序保留 `-10` 到 `-1` 这十个地址存放变量，地址 `0` 作为临时指针：

| 地址 | 名称 | 用途 |
| --- | --- | --- |
| `-1` | `P` | 逐次减一的一路搜索值；也复用于构造负数输出 |
| `-2` | `Q` | 逐次加一的一路搜索值 |
| `-3` | `K` | 步数或剩余次数 |
| `-4` | `TMP` | 更新变量前保存旧值 |
| `-5` | `RUN` | 是否继续循环，取值为 0 或 1 |
| `-6` | `DONE` | 当前分支是否已处理，取值为 0 或 1 |
| `-7` | `MAG` | 输入的绝对值 |
| `-8` | `SIGN` | 负数为 1，非负数为 0 |
| `-9` | `POS` | 正数部分的累计幅值 |
| `-10` | `NEG` | 负数部分的累计幅值 |

始终保持以下内存约束：

1. 除这十个地址及地址 `0` 外，所有地址的内存值均为 `0`。
2. 变量槽中的数据只能是非负整数，或小于等于 `-11` 的负整数。
3. 变量数据不能等于任何一个保留地址，即不能落入 `[-10, -1]`。

这样，若某个变量槽存着非零数据 V，就一定有 `memory[V] = 0`。后续的寻址推导都依赖这个条件。

## 三、先清 0 槽，统一选择目标槽

对任意保留地址 X，考虑：

```text
&0 ^1 &X ^3 &0 ^2
```

逐步推导如下。

首先，`&0 ^1` 直接令 `memory[0] = 0`。深度为 1，无须跳转，操作地址就是当前值 `0`。

接下来，`&X ^3` 从 X 出发跳转两次。设 X 的旧值为 U：

```text
若 U = 0： X → 0 → 0
若 U ≠ 0：X → U → 0
```

第二种情况成立，是因为 U 避开了所有保留地址。两种情况下最终地址都是 `0`，所以这条指令都会执行：

```text
memory[0] = X
```

最后执行 `&0 ^2`。它从 `0` 跳转一次，到达 `memory[0]` 所指的 X，再把当前值 `0` 写进去：

```text
memory[X] = 0
```

因此，这个模板执行后的状态统一为：

```text
memory[0] = X
memory[X] = 0
```

这解决了前面程序中“旧值为零时，选择目标槽需要另算深度”的问题。

### 把新值写入目标槽

此时让表达式产生新值 V，再执行 `^3`。

若 V 非零，并满足存储约束，寻址路径为：

```text
V → 0 → X
```

因此执行 `memory[X] = V`。

若 V 恰好为 `0`，路径则是：

```text
0 → X → 0
```

这次写入的是 `memory[0] = 0`。但 X 已经被提前清零，所以目标赋值 `memory[X] = 0` 仍然成立。只是临时指针最后变成了 `0`，下次赋值会重新设置它。

所以，统一赋值模板为：

```text
&0 ^1 &X ^3 &0 ^2 EXPRESSION ^3
```

表达式必须产生符合约束的数据，并且不能依赖 X 的旧值或 0 槽的旧值，因为它们已经被前面的准备指令改写。

例如实现 `X = X + 1`，必须先把 X 的旧值保存到另一个临时槽，再清 X，最后读临时槽、自增、写回。这就是程序中 `change()` 宏的作用。

## 四、另一种技巧：用自环保存任意有符号整数

这一技巧可以单独构造一个不限制载荷取值的寄存器，但完整 A+B 的多变量存储使用的是上一节的方法。

从空内存开始执行：

```text
&-1 ^2 ^1
```

第一条写入指令 `^2` 沿着 `-1 → 0`，令 `memory[0] = -1`。它不改变 `view`，所以随后的 `^1` 再令 `memory[-1] = -1`。

于是形成：

```text
memory[0] = -1
memory[-1] = -1
```

此时，任意整数出发，跳转两次都会到达 `-1`：

```text
-1：      -1 → -1 → -1
0：        0 → -1 → -1
其余整数： V →  0 → -1
```

所以：

```text
&-1 ^2 ^1 @input ^3
```

能把任意输入写入 `memory[-1]`，包括 `0`，也包括目标地址本身 `-1`。

读取时执行：

```text
&-1 *1
```

它把旧数据交换到 `view`，同时把 `-1` 写回 `memory[-1]`，恢复自环。此后对 `view` 运算，再执行 `^3`，就能保存新结果。

例如下面这段会读取任意整数，先加一写回，再减一写回，最后输出原数：

```text
&-1 ^2 ^1 @input ^3
&-1 *1 @+ ^3
&-1 *1 @- ^3
&-1 *1 @print
```

它依赖“所有地址都能在两次跳转内到达目标自环”的结构。增加其他非零内存后，必须重新证明可达性和所需深度，不能直接把它当成通用的多寄存器赋值模板。

## 五、只用零测试实现条件分支

DSL 没有 `if`，但循环可以改造成只执行一次的非零分支：

```text
条件表达式
[
  分支体
  &0
]
```

条件为零时跳过；条件非零时进入，分支末尾的 `&0` 保证退出。这里的中文行是模板说明，不是实际 DSL 指令。

如果还需要“否则”分支，就用一个取值为 0 或 1 的 `DONE` 变量记录是否已经处理：

```text
DONE = 0：尚未处理
DONE = 1：已经处理
```

检查 `DONE - 1` 即可判断是否仍需处理：未处理时得到 `-1`，进入非零分支；已处理时得到 `0`，跳过。

完整程序的有限情况分类正是用这一方法展开，没有增加新的运行时操作。

## 六、先处理可能发生地址碰撞的输入

任意负整数都可能等于某个保留地址。例如输入 `-4` 时，如果直接把它存入普通变量槽，后续沿这个数据寻址就会碰到临时变量 `TMP`。

因此，读入后先检查十二种情况：

```text
x = 0、-1、-2、……、-11
```

做法是依次对以下值进行零测试：

```text
x、x+1、x+2、……、x+11
```

若在第 j 次偏移处遇到零，就知道原输入为 `-j`，可以直接设置：

```text
MAG = j
SIGN = 0（j = 0），或 1（j > 0）
```

这些原始负输入不会被写入普通变量槽，存进去的只有非负幅值和 0/1 符号。

若所有零测试都未命中，原输入必定满足以下两者之一：

```text
x > 0
x < -11
```

程序撤销前面的十一次自增，恢复 x，再把它保存到搜索变量 P 中。此时 x 已经避开所有保留地址。

这里额外分类 `-11`，是为了让后面的搜索至少执行一步才到达负侧边界。

## 七、双向搜索：不用大小比较判断符号

对剩余输入，初始化：

```text
p = x
q = x
k = 0
```

每轮执行：

```text
p = p - 1
q = q + 1
k = k + 1
```

只要 p 和 q+11 都非零，就继续下一轮；否则停止。这只需要普通零测试。

### 情况一：x 为正

经过 k 轮后：

```text
p = x - k
q = x + k
```

p 会在第 x 轮到达 `0`，而 q 始终为正，不可能到达 `-11`。因此：

```text
k = x
MAG = k
SIGN = 0
```

p 在停止前一直非负，q 一直为正，两个变量都不会存入保留地址范围内的数据。

### 情况二：x 小于 -11

p 不断减小，永远到不了 `0`。q 则在下式成立时到达负侧边界：

```text
x + k = -11
k = -11 - x
```

因此：

```text
|x| = -x = k + 11
MAG = k + 11
SIGN = 1
```

停止时 q 恰好为 `-11`；在此之前，p、q 均不大于 `-11`。所以搜索全程仍满足存储约束。

例如输入 `-14`：

| 已执行轮数 k | p | q |
| --- | --- | --- |
| 0 | -14 | -14 |
| 1 | -15 | -13 |
| 2 | -16 | -12 |
| 3 | -17 | -11 |

第三轮检测到 `q+11 = 0`，得到 `MAG = 3+11 = 14`，符号为负。

两种情况都能在有限轮数内停止，且覆盖了有限分类之外的全部整数。因此整个符号与幅值解码过程覆盖所有整数。

常数 `11` 来自十个保留地址的边界，不是对输入绝对值的上限。

## 八、把有符号加法转成非负计数

设 `POS`、`NEG` 初始均为 `0`。每解码一个输入：

- 输入非负时，把其幅值逐次加到 `POS`。
- 输入为负时，把其幅值逐次加到 `NEG`。

两个输入处理完后，有：

```text
A + B = POS - NEG
```

随后只要 POS、NEG 都非零，就同时各减一。每轮减法都保持差值不变，直到至少一个计数器为零。

例如 `A=42`、`B=-100`：

```text
累计后：POS = 42，NEG = 100
抵消后：POS = 0， NEG = 58
结果：  -58
```

这一部分操作的变量始终是非负整数，直接使用前面的统一赋值模板即可。

## 九、如何安全地输出负结果

抵消后，若 NEG 为零，直接输出 POS；否则需要输出 `-NEG`。

不能让一个存储槽从 `0` 开始逐次减一，因为它会经过 `-1` 到 `-10`，违反存储约束。

解决方法仍是把有限情况和其余情况分开。

当 NEG 的幅值为 `0` 到 `11` 时，分类后直接用立即数输出。例如结果为 `-4`：

```text
&-4 @print
```

这个负数只出现在 `view` 中，不会作为数据存入变量槽，因此不会破坏内存结构。

若幅值 m 大于 `11`，则初始化：

```text
P = -11
K = m - 11
```

循环 K 次，每次令 P、K 各减一。最后：

```text
P = -11 - (m - 11) = -m
```

整个过程中 P 始终不大于 `-11`，K 始终非负，仍满足存储约束。最后读取 P 并输出即可。

from tools.runtime import IRBuilder, Runtime, std_register

## 十一、复杂度与验证结果

按基本指令的执行次数计，时间复杂度为：

```text
O(|A| + |B| + 1)
```

程序使用十个变量槽和一个临时指针槽。但运行器使用 `defaultdict`，读取原本为零的地址也会创建字典项，所以实际内存字典的条目数仍可能随输入幅值线性增长。固定变量槽数量不代表字典实际占用为常量。

原推导阶段的验证程序使用未修改的基准运行器，只替换标准输入并捕获标准输出。历史验证内容包括：

- 检查 IR 中不存在直接寻址指令。
- 检查 DSL 只调用上述四种基本标准操作。
- 81 组变量赋值测试，覆盖旧值、新值为零以及 101 位整数。
- 63 组自环寄存器测试，覆盖地址本身 `-1`、零和 101 位输入。
- 201 组独立的符号与幅值解码测试。
- 2664 组完整 A+B 测试，包含 `[-24,24] × [-24,24]` 全枚举、固定随机种子的正负混合测试，以及幅值约为 10000 的部分边界样例。

每组完整测试都要求恰好消耗两个输入、恰好输出一行，并与测试端独立计算的 A+B 结果一致。

上述历史验证均已通过，推导时没有遇到疑似基准实现 bug 的情况。归档仓库的当前测试另见 `tests/test_archive.py`：包含全部样例、`[-12,12] × [-12,12]` 的 625 组加法，以及生成器与纯 DSL 文件一致性检查；历史验证范围不冒充本仓库每次 CI 的执行范围。
